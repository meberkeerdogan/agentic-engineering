# v0.1 Product Scope

**Status:** Frozen on 2026-08-20

`v0.1` is an experimental toolkit with one supported path: the
[verified single-agent workflow](../workflows/verified-single-agent-v0.1.md).
It is not a claim that every included research module improves coding agents.

## Included in the supported product

| Capability | Why it is included |
| --- | --- |
| Active specification | Removes superseded requirements from the current contract while preserving their history. |
| Bounded single-agent execution | Keeps work and retries explicit instead of allowing an uncontrolled loop. |
| Independent evidence checks | Prevents the executor's own completion claim from being treated as proof. |
| Append-only verified state | Makes progress traceable and rejects unevidenced or tampered transitions. |
| Regression-safe evaluation | Reports partial target progress but refuses strict success when old behavior breaks. |
| Structured run output | Gives users inspectable specifications, evidence, state, and final status. |
| Codex CLI adapter | Provides the first tested live-agent connection with isolation, preflight checks, budgets, and explicit confirmation. |
| Deterministic experiment harness | Lets maintainers compare later interventions without changing the default from anecdotes. |

These capabilities have clear engineering value even though the project does not
yet claim a measured improvement in general agent success rates.

## Included only as experimental modules

| Capability | Current evidence and decision |
| --- | --- |
| Phase memory | Safe in the completed 18-cell campaign, but completion remained `9/9` in both arms and treatment cost increased. Keep optional. |
| Adaptive dependency planning | Did not beat its sentinel control. Keep optional. |
| Watchdog advice | Detection and calibration infrastructure works, but intervention value is not established. Observe only. |
| Generated property evidence | The safety interface works, but general task benefit is not established. Keep optional. |
| Multi-agent execution | Isolation and integration work offline, but it has not beaten the simpler verified single-agent path. Keep optional. |
| Learning Companion | The teaching boundary is safe and proposal-only, but learning benefit and runtime cost are not yet measured. Keep optional. |
| Paper reproduction tools | Useful research infrastructure, not part of an ordinary coding run. |

Experimental modules may remain installed and documented. They must be disabled
by default and clearly labelled when a user selects them.

## Claims allowed for v0.1

We may say that the toolkit:

- separates execution claims from independent verification;
- records evidence-backed progress and protected regressions;
- supports isolated, budgeted Codex CLI experiments;
- provides deterministic offline tests and reusable evaluation fixtures.

We must not say that the workflow generally improves agent success, lowers cost,
or outperforms other systems until broader held-out experiments support that claim.

## Promotion rule

An experimental capability may become a later default only when:

1. the relevant research review and comparison are declared before testing;
2. representative tasks include hidden checks and protected old behavior;
3. control and treatment are run with repeated paired seeds;
4. the treatment produces a meaningful benefit on its declared target;
5. completion, regression, false-completion, cost, and time remain acceptable.

A neutral or negative result keeps the capability optional. It does not trigger an
endless redesign cycle or block the current release.

## Release boundary

Before `v0.1.0`, product work is limited to the one-command run path, a realistic
example, short user documentation, fresh-checkout acceptance testing, and fixes
that block those tasks. Everything else belongs to a later bounded release or
research project.
